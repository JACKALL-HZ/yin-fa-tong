# 延迟支付技术方案

## 原理概述

银发通采用 **RabbitMQ 延迟交换机（x-delayed-message）** 实现 15 分钟未支付自动取消。

核心思想：订单创建时向 RabbitMQ 发送一条"延迟消息"，消息在队列中"休眠"指定时间后才被消费者收到。消费者检查订单是否已支付——未支付则取消订单并回滚号源。

## 流程图

```
用户提交预约
    │
    ▼
扣减 Redis 号源（Lua 原子操作）
    │
    ▼
创建 MySQL 订单（pay_status=1 待支付）
    │
    ▼
发送延迟消息到 RabbitMQ（delay=15min）
    │
    ▼
┌───────────────────────────────────────────┐
│           15 分钟倒计时开始                 │
│                                           │
│  ┌─ 用户支付成功？                         │
│  │   是 → 更新 pay_status=2，订单完成      │
│  │   否 → 等待超时                         │
│  └─────────────────────────────────────────┘
│                                           │
│  15 分钟到期，消息投递到消费者               │
└───────────────────────────────────────────┘
    │
    ▼
消费者收到消息，检查 pay_status
    │
    ├─ pay_status=1（仍待支付）→ 回滚号源 + 更新为超时取消
    └─ pay_status=2（已支付）→ 忽略，不做任何操作
```

## 技术栈

| 组件 | 作用 |
|------|------|
| RabbitMQ x-delayed-message 插件 | 消息延迟投递 |
| Redis + Lua 脚本 | 原子扣减/回滚号源 |
| MySQL | 订单状态持久化 |
| aio-pika | Python 异步 RabbitMQ 客户端 |

## 代码实现

### 1. RabbitMQ 交换机配置

```python
# backend/app/shared/rabbitmq.py

import aio_pika

async def setup_exchanges(channel: aio_pika.Channel):
    """声明交换机"""

    # 延迟交换机（x-delayed-message 类型）
    await channel.declare_exchange(
        "ex_delay",
        type="x-delayed-message",        # 延迟消息类型
        durable=True,
        arguments={"x-delayed-type": "direct"},  # 延迟后按 direct 路由
    )

    # 普通 Direct 交换机（挂号成功通知等）
    await channel.declare_exchange("ex_reserve", type="direct", durable=True)


async def publish_delay(routing_key: str, body: dict, delay_ms: int):
    """发送延迟消息"""
    connection = await get_rabbitmq_connection()
    channel = await connection.channel()
    exchange = await channel.get_exchange("ex_delay")

    message = aio_pika.Message(
        body=json.dumps(body).encode(),
        headers={"x-delay": delay_ms},   # 关键：延迟毫秒数
        delivery_mode=aio_pika.DeliveryMode.PERSISTENT,
    )

    await exchange.publish(message, routing_key=routing_key)
```

### 2. 消息生产者（订单创建时发送）

```python
# backend/app/reserve/mq/producer.py

from app.shared.rabbitmq import publish_delay

TIMEOUT_MS = 15 * 60 * 1000  # 15 分钟 = 900000 毫秒


async def send_payment_timeout(reserve_id: int, schedule_id: int, source_type: str):
    """发送延时取消消息：15 分钟后自动取消未支付订单"""
    await publish_delay(
        routing_key="delay.task",
        body={
            "type": "payment_timeout",
            "reserve_id": reserve_id,
            "schedule_id": schedule_id,
            "source_type": source_type,
        },
        delay_ms=TIMEOUT_MS,
    )
```

### 3. 消息消费者（超时处理）

```python
# backend/app/reserve/mq/consumer.py

import json
import logging
import aio_pika
from app.shared.redis import rollback_source_redis

logger = logging.getLogger(__name__)


async def on_delay_message(message: aio_pika.IncomingMessage):
    """处理延时消息"""
    async with message.process():
        body = json.loads(message.body.decode())
        msg_type = body.get("type")

        if msg_type == "payment_timeout":
            reserve_id = body["reserve_id"]
            schedule_id = body["schedule_id"]
            source_type = body["source_type"]

            # 回滚 Redis 号源
            await rollback_source_redis(schedule_id, source_type)

            # 检查订单状态，仍为待支付则取消
            from app.shared.database import AsyncSessionLocal
            from app.reserve.repository import get_by_id, update_status

            async with AsyncSessionLocal() as session:
                reserve = await get_by_id(session, reserve_id)
                if reserve and reserve.pay_status == 1:  # 仍为待支付
                    await update_status(session, reserve, pay_status=3, order_status=4)
                    await session.commit()
                    logger.info("订单已超时取消 reserve_id=%s", reserve_id)
                else:
                    logger.info("订单已支付，跳过取消 reserve_id=%s", reserve_id)


async def start_consumer():
    """启动延时队列消费者"""
    connection = await aio_pika.connect_robust(
        f"amqp://guest:guest@rabbitmq:5672/"
    )
    channel = await connection.channel()
    await channel.set_qos(prefetch_count=10)
    queue = await channel.declare_queue("q_delay_tasks", durable=True)
    await queue.consume(on_delay_message)
    return connection
```

### 4. Redis 号源 Lua 脚本（原子操作）

```python
# backend/app/shared/redis.py

# 扣减号源
LUA_DECREASE_SOURCE = """
local key_normal = KEYS[1]
local key_elder = KEYS[2]
local source_type = ARGV[1]

if source_type == 'elder' then
    local val = redis.call('GET', key_elder)
    if not val or tonumber(val) <= 0 then return -1 end
    redis.call('DECR', key_elder)
else
    local val = redis.call('GET', key_normal)
    if not val or tonumber(val) <= 0 then return -1 end
    redis.call('DECR', key_normal)
end
return 1
"""

# 回滚号源
LUA_ROLLBACK_SOURCE = """
local key = KEYS[1]
redis.call('INCR', key)
return 1
"""

async def decrease_source_redis(schedule_id: int, source_type: str) -> bool:
    """原子扣减号源"""
    r = await get_redis()
    key_normal = f"source:{schedule_id}:normal"
    key_elder = f"source:{schedule_id}:elder"
    result = await r.eval(LUA_DECREASE_SOURCE, 2, key_normal, key_elder, source_type)
    return result == 1

async def rollback_source_redis(schedule_id: int, source_type: str):
    """回滚号源"""
    r = await get_redis()
    key = f"source:{schedule_id}:{source_type}"
    await r.eval(LUA_ROLLBACK_SOURCE, 1, key)
```

### 5. 订单创建时调用（串联全流程）

```python
# backend/app/reserve/service.py（简化版）

from app.reserve.mq.producer import send_payment_timeout

async def create_reserve(session, req, user_id):
    """创建预约订单"""

    # 1. Redis 原子扣减号源
    success = await decrease_source_redis(req.schedule_id, req.source_type)
    if not success:
        raise ValueError("号源已满")

    # 2. 创建订单（待支付状态）
    reserve = ReserveModel(
        user_id=user_id,
        schedule_id=req.schedule_id,
        elder_bind_id=req.elder_bind_id,
        source_type=req.source_type,
        pay_status=1,      # 待支付
        order_status=1,    # 待支付
        queue_code=generate_queue_code(),
    )
    session.add(reserve)
    await session.flush()

    # 3. 发送 15 分钟延迟取消消息
    await send_payment_timeout(
        reserve_id=reserve.id,
        schedule_id=req.schedule_id,
        source_type=req.source_type,
    )

    await session.commit()
    return reserve
```

### 6. 支付成功时的处理

```python
# backend/app/payment/service.py（简化版）

async def handle_payment_success(session, reserve):
    """支付成功处理"""
    reserve.pay_status = 2    # 已支付
    reserve.order_status = 2  # 已预约
    reserve.queue_status = 1  # 等待中
    await session.commit()

    # 注意：不需要取消延迟消息
    # 消费者收到消息后会检查 pay_status，发现已支付则自动跳过
```

## 关键设计决策

### 为什么不用定时轮询数据库？

| 方案 | 优点 | 缺点 |
|------|------|------|
| RabbitMQ 延迟消息 | 实时性高、不占数据库资源、天然分布式 | 依赖 RabbitMQ |
| 定时任务轮询 DB | 实现简单 | 有延迟、数据库压力大、不适合高并发 |

### 为什么支付成功后不取消延迟消息？

消费者代码中做了幂等检查：

```python
if reserve and reserve.pay_status == 1:  # 仍为待支付才取消
    # 执行取消逻辑
else:
    # 已支付，跳过
```

这样做的好处：
1. 代码更简单，不需要额外的取消消息逻辑
2. 天然幂等，重复消费不会出问题
3. 减少与 RabbitMQ 的交互

### Redis Lua 脚本为什么是原子的？

Lua 脚本在 Redis 中是单线程执行的，整个脚本要么全部执行，要么全部不执行。在高并发场景下，多个用户同时抢同一个号源时，不会出现"超卖"问题。

## 部署注意事项

1. RabbitMQ 需要安装 `x-delayed-message` 插件：
   ```bash
   rabbitmq-plugins enable rabbitmq_delayed_message_exchange
   ```

2. 消费者需要独立进程运行（Docker Compose 中已配置）

3. 延迟时间在 `producer.py` 中的 `TIMEOUT_MS` 常量控制，修改后需重启服务
