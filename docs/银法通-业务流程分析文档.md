## 一、平台概述

银发通（Silver Hair Connect）面向老年群体及其子女，提供**线上预约挂号、AI 智能导诊、公益志愿者陪诊**一站式就医辅助服务。

### 1.1 用户角色

| 角色 | user_type | 说明 |
|------|-----------|------|
| 老年用户 | 1 | 直接使用平台挂号、导诊的老年人 |
| 子女用户 | 2 | 为长辈代办挂号、预约陪诊的子女 |
| 管理员 | 3 | 医院运营人员，管理排班/志愿者/订单 |

### 1.2 核心业务域

```
┌─────────────────────────────────────────────────────┐
│                    银发通平台                         │
├──────────┬──────────┬──────────┬──────────┬──────────┤
│ 用户中心 │ 预约挂号 │ 智能导诊 │ 陪诊服务 │ 健康管理 │
│ 注册登录 │ 排班号源 │ 症状匹配 │ 志愿者   │ 提醒     │
│ 长辈绑定 │ 候诊排队 │ Dify AI  │ 订单管理 │ 体检报告 │
│ 个人中心 │ 在线支付 │ ES搜索   │ 服务评价 │ 消息中心 │
└──────────┴──────────┴──────────┴──────────┴──────────┘
```

## 三、模块分层拆解与子活动流程图

### 3.1 认证授权模块（Auth）

#### 3.1.1 业务说明

支持三种登录方式：手机号密码、子女亲情登录（共用密码登录接口）、支付宝 OAuth 扫码。微信/银联预留接口。

#### 3.1.2 注册流程

```mermaid
flowchart TD
    A([注册入口]) --> B[填写手机号/密码/昵称]
    B --> C{用户类型}
    C -->|长者| D[user_type=1]
    C -->|子女| E[user_type=2]
    C -->|管理员| F[输入管理员注册码]
    F --> G{码是否正确?}
    G -->|否| H[拒绝注册]
    G -->|是| I[user_type=3]
    D --> J[后端校验]
    E --> J
    I --> J
    J --> K{手机号格式?}
    K -->|非11位| L[返回错误]
    K -->|11位数字| M{账号已存在?}
    M -->|是| N[返回409冲突]
    M -->|否| O[bcrypt加密密码]
    O --> P[写入tb_user]
    P --> Q[生成JWT Token]
    Q --> R[返回token+用户信息]
```

#### 3.1.3 登录流程

```mermaid
flowchart TD
    A([登录入口]) --> B{登录方式}
    B -->|手机号| C[输入手机号+密码]
    B -->|支付宝扫码| D[跳转支付宝OAuth]

    C --> E[后端查库校验]
    E --> F{密码匹配?}
    F -->|否| G[返回401]
    F -->|是| H[生成JWT返回]

    D --> I[支付宝授权页]
    I --> J[用户扫码授权]
    J --> K[回调/auth/callback]
    K --> L[auth_code换access_token]
    L --> M[获取用户信息]
    M --> N{首次登录?}
    N -->|是| O[自动注册]
    N -->|否| P[直接登录]
    O --> H
    P --> H
```

#### 3.1.4 业务规则

| 规则 | 说明 |
|------|------|
| 用户名格式 | 必须为11位纯数字手机号 |
| 密码要求 | >=6位，bcrypt单向加密存储 |
| 管理员注册 | 需提供 `admin_code`（配置项 `ADMIN_REGISTER_CODE`） |
| JWT有效期 | 24小时（1440分钟） |
| 支付宝首次登录 | 自动注册为老年用户（user_type=1） |
| 生产安全 | JWT_SECRET_KEY 为默认值时拒绝启动 |

### 3.3 预约挂号模块（Reserve + Schedule + Queue）

#### 3.3.1 业务说明

平台核心模块，涵盖排班查看、号源管理、预约下单、在线支付、候诊排队全链路。

#### 3.3.2 预约挂号完整流程

```mermaid
flowchart TD
    A([查看排班]) --> B[选择医生排班]
    B --> C[进入预约确认页]
    C --> D{选择号源类型}
    D -->|自主挂号| E[normal普通号]
    D -->|老年优先| F[elder优先号]
    D -->|子女代办| G[选择已绑定长辈]

    D --> H{个人信息完善?}
    H -->|否| I[提示先完善信息]
    H -->|是| J[确认预约并支付]

    J --> K[POST /api/reserves]
    K --> L{Redis SET NX去重}
    L -->|已存在| M[返回重复预约错误]
    L -->|不存在| N{Lua原子扣减号源}
    N -->|不足| O[返回号源不足]
    N -->|成功| P[创建数据库订单]
    P --> Q[生成候诊编号]
    Q --> R[注册Redis候诊队列]
    R --> S[RabbitMQ发送延时取消消息]
    S --> T[返回预约结果]
    T --> U[展示候诊编号]
```

#### 3.3.3 支付与超时流程

```mermaid
flowchart TD
    A([预约成功]) --> B[15分钟倒计时]
    B --> C{用户操作}
    C -->|点击支付| D[POST /api/payment/create]
    C -->|超时未支付| E[RabbitMQ延时消息触发]

    D --> F{PAY_MODE}
    F -->|sandbox| G[生成支付宝收银台URL]
    F -->|mock| H[模拟支付直接完成]

    G --> I[用户在支付宝完成支付]
    I --> J[支付宝异步回调POST /api/payment/notify]
    J --> K{RSA2验签}
    K -->|失败| L[返回failure]
    K -->|成功| M{trade_status}
    M -->|TRADE_SUCCESS| N[mark_paid + 更新订单状态]
    M -->|TRADE_CLOSED| O[标记支付记录关闭]

    E --> P[消费者查询订单]
    P --> Q{仍为待支付?}
    Q -->|是| R[更新为超时取消]
    R --> S[回滚Redis号源]
    Q -->|否| T[无需处理]

    N --> U[入候诊队列]
    H --> U
```

#### 3.3.4 候诊排队流程

```mermaid
flowchart TD
    A([支付成功]) --> B[获得候诊编号 NK+日期+流水号]
    B --> C[进入候诊状态]
    C --> D{查询排队位置}
    D --> E[GET /api/queue/my-position/{queue_code}]
    E --> F[返回: 我的编号/当前叫号/前方人数/预估等待]

    G([管理员/医生]) --> H[POST /api/queue/call-next/{schedule_id}]
    H --> I[递增queue:schedule_id:current]
    I --> J[发送候诊提醒消息]

    K([排班日期过后]) --> L[自动更新order_status=3已就诊]
```

#### 3.3.5 取消预约流程

```mermaid
flowchart TD
    A([用户点击取消]) --> B{订单状态}
    B -->|已取消| C[提示不可重复取消]
    B -->|其他| D{就诊日期}
    D -->|<=今天| E[提示到窗口办理]
    D -->|>今天| F[POST /api/reserves/{id}/cancel]
    F --> G[更新order_status=4]
    G --> H[回滚Redis号源]
    H --> I[清除去重标记]
```

#### 3.3.6 业务规则

| 规则 | 说明 |
|------|------|
| 支付超时 | 15分钟内未支付自动取消，RabbitMQ延时消息+定时任务兜底 |
| 预约去重 | Redis SET NX，key=`reserve_dedup:{schedule_id}:{user_id}`，TTL 900s |
| 号源原子扣减 | Lua脚本保证检查+扣减原子性，防止并发超卖 |
| 号源回滚 | 取消/超时自动INCRBY恢复 |
| 号源对账 | 每小时定时任务，以MySQL为准修复Redis |
| 候诊编号 | 格式 `NK{YYYYMMDD}{reserve_id:04d}` |
| 候诊预估 | 每人5分钟，`前方人数 × 5 = 预估等待分钟` |
| 当天不可取消 | `work_date <= today` 需到窗口办理 |
| 自动过期 | 查询详情时，排班日期已过+已预约 → 自动更新为已就诊 |
| 号源类型 | normal（普通号）和 elder（老年优先号）独立计数 |

### 3.4 在线支付模块（Payment）

#### 3.4.1 业务说明

支持支付宝沙箱支付和模拟支付两种模式，含创建订单、异步回调、主动同步三条路径。

#### 3.4.2 支付全流程

```mermaid
flowchart TD
    A([创建支付]) --> B[校验预约订单]
    B --> C[查询挂号费]
    C --> D{已有支付记录?}
    D -->|有+未超时| E[复用原订单号]
    D -->|有+已超时| F[关闭旧记录+报错]
    D -->|无| G[生成新订单号 YFT+时间戳+随机]

    E --> H{PAY_MODE}
    G --> H
    H -->|sandbox| I[调用支付宝SDK page_execute]
    H -->|mock| J[直接更新订单为已支付]

    I --> K[返回支付宝收银台URL]
    K --> L[前端window.location.href跳转]
    L --> M[用户在支付宝完成支付]
    M --> N[支付宝POST异步通知]
    N --> O[验签+幂等处理]
    O --> P[更新支付记录+订单状态]
    P --> Q[入候诊队列]

    J --> Q

    R([支付宝回调未到达]) --> S[前端调用sync接口]
    S --> T[主动查询支付宝trade_query]
    T --> U[同步本地状态]
```

#### 3.4.3 业务规则

| 规则 | 说明 |
|------|------|
| 订单号格式 | `YFT{时间戳}{6位随机大写hex}` |
| 支付超时 | 15分钟 |
| 幂等保障 | `mark_paid` 使用 `WHERE pay_status=1` 防并发重复更新 |
| 验签策略 | fail-closed，验签失败直接返回failure |
| 降级方案 | sandbox不可用时可切mock模式 |
| 三重确认 | 异步回调 + 同步跳转 + 主动查询 |

### 3.5 AI智能导诊模块（Guide）

双引擎策略：Dify AI（主）+ 本地规则引擎（兜底）。输入症状文本，推荐科室+用药建议。

    D --> F
    E --> F

    F --> G{Dify API Key配置?}
    G -->|否| H[本地规则引擎]
    G -->|是| I[调用Dify Chatbot]
    I --> J{调用成功?}
    J -->|否| H
    J -->|是| K[解析JSON响应]
    K --> L[提取科室推荐+用药建议+注意事项]

    L --> Q[返回GuideResponse]

### 3.6 ES搜索模块（Search）

#### 3.6.1 业务说明

基于Elasticsearch的全文搜索，覆盖医院、科室、医生、症状四类数据，使用IK中文分词器。

#### 3.6.2 搜索流程

```mermaid
flowchart TD
    A([用户输入关键词]) --> B[GET /api/search?keyword=xxx&type=all]
    B --> C{type参数}
    C -->|all| D[搜索全部4个索引]
    C -->|hospital| E[yft_hospital]
    C -->|department| F[yft_department]
    C -->|doctor| G[yft_doctor]
    C -->|symptom| H[yft_symptom]

    D --> I[multi_match + best_fields]
    E --> I
    F --> I
    G --> I
    H --> I

    I --> J[按相关度评分排序]
    J --> K[归一化为SearchResultItem]
    K --> L[返回type/id/title/subtitle/route]
    L --> M[前端展示可点击结果]
    M --> N[点击跳转对应页面]
```

#### 3.6.3 数据同步策略

```mermaid
flowchart TD
    A([数据变更]) --> B{变更类型}
    B -->|单条CUD| C[增量同步钩子]
    B -->|批量/全量| D[POST /api/search/sync]

    C --> E[register_es_hook注册回调]
    E --> F[DB commit成功后执行]
    F --> G[ES单条index/update/delete]
    G --> H{ES可用?}
    H -->|否| I[记录warning,下次全量补齐]
    H -->|是| J[同步成功]

    D --> K[delete_index + create + bulk_index]
    K --> L[es.indices.refresh]
    L --> M[立即可搜]
```

#### 3.6.4 索引结构

| 索引 | 搜索字段 | 分词策略 |
|------|----------|----------|
| yft_hospital | hospital_name^3, address | ik_max_word索引 / ik_smart搜索 |
| yft_department | dept_name^3, hospital_name | 同上 |
| yft_doctor | doctor_name^3, specialty^2, dept_name, hospital_name, doctor_title | 同上 |
| yft_symptom | keywords^3, dept_name | 同上 |

### 3.7 陪诊服务模块（Accompany）

#### 3.7.2 陪诊下单与服务流程

```mermaid
flowchart TD
    A([浏览志愿者列表]) --> B[选择志愿者]
    B --> C[查看详情]
    C --> D{已绑定长辈?}
    D -->|否| E[提示先绑定长辈]
    D -->|是| F[选择陪诊日期]
    F --> G[提交订单]
    G --> H[POST /api/accompany-orders]
    H --> I[order_status=1待审核]
    I --> J[RabbitMQ推送管理员通知]

    K([管理员]) --> L{审核}
    L -->|通过| M[order_status=2待服务]
    L -->|拒绝| N[order_status=5已取消]

    M --> O[陪诊当日]
    O --> P[POST /start order_status=3服务中]
    P --> Q[服务完成]
    Q --> R[POST /complete order_status=4已完成]

    R --> S[用户评价]
    S --> T[POST /review]
    T --> U[保存评分1-5+文字评价]
    U --> V[更新志愿者加权平均分]

    W([自动过期]) --> X{陪诊日期已过?}
    X -->|待审核/待服务| Y[自动取消]
    X -->|服务中| Z[自动完成]
```

#### 3.7.3 评价算法

```
新评分 = (旧评分 × 旧次数 + 新评分) / (旧次数 + 1)
```

#### 3.7.4 业务规则

| 规则 | 说明 |
|------|------|
| 志愿者状态 | status=1可预约 / status=0不可预约 |
| 订单状态流转 | 待审核(1)→待服务(2)→服务中(3)→已完成(4)，可→已取消(5) |
| 评价时机 | order_status=3（服务中）时可评价 |
| 评价后自动完成 | 评价后自动更新为order_status=4 |
| 自动过期 | 日期过期+待审核/待服务→取消，日期过期+服务中→完成 |
| 价格 | 政府补贴，价格0元 |
| 长辈绑定 | 子女需先绑定长辈才能预约陪诊 |

### 3.8 健康提醒模块（Reminder）

#### 3.8.1 业务说明

基于RabbitMQ延迟队列的定时提醒，支持用药/复诊/体检三种类型，可设置每日循环。

#### 3.8.2 提醒创建与推送流程

```mermaid
flowchart TD
    A([创建健康提醒]) --> B[选择提醒类型]
    B --> C[设置提醒时间 HH:MM]
    C --> D[填写提醒内容]
    D --> E[选择关联长辈 可选]
    E --> F[设置重复天数 0=不重复]
    F --> G[POST /api/reminders]
    G --> H[计算到目标时间的延时毫秒]
    H --> I[publish_delay到RabbitMQ]
    I --> J[写入tb_health_reminder]

    K([延时到达]) --> L[消费者on_health_reminder触发]
    L --> M{提醒状态?}
    M -->|已删除/已停用| N[丢弃,不续发]
    M -->|正常| O[写入tb_message]
    O --> P{repeat_days > 0?}
    P -->|是| Q[计算下一周期延时]
    Q --> R[续发延迟消息]
    P -->|否| S[结束]
```

#### 3.8.3 业务规则

| 规则 | 说明 |
|------|------|
| 提醒类型 | medicine(用药) / revisit(复诊) / checkup(体检) |
| 时间格式 | HH:MM，自动计算到下一目标时间的延时 |
| 循环机制 | repeat_days > 0 时每日续发延迟消息 |
| 停用/删除 | 消费者遇到 is_deleted=1 或 is_active=0 直接丢弃，中断续发链 |
| 消息类型 | 写入tb_message时msg_type=4（健康提醒） |

### 3.9 消息中心模块（Message）

#### 3.9.1 业务说明

统一消息入口，汇集系统通知、挂号通知、候诊通知、健康提醒、陪诊通知。

#### 3.9.2 消息类型

| msg_type | 类型 | 来源 |
|----------|------|------|
| 1 | 系统通知 | 管理员/系统 |
| 2 | 挂号通知 | 预约成功时MQ推送 |
| 3 | 候诊通知 | 叫号/顺位变化时MQ推送 |
| 4 | 健康提醒 | 延迟队列消费者写入 |
| 5 | 陪诊通知 | 陪诊订单状态变更 |

#### 3.9.3 接口

- `GET /api/messages` — 消息列表（支持msg_type/read_status筛选）
- `POST /api/messages/{id}/read` — 标记已读
- `GET /api/messages/unread-count` — 未读数量

### 3.10 体检报告模块（Report）

#### 3.10.1 业务说明

子女上传长辈体检报告图片，系统OCR识别指标值，规则引擎生成通俗化解读。

#### 3.10.2 报告处理流程

```mermaid
flowchart TD
    A([上传体检报告]) --> B[选择关联长辈]
    B --> C[选择图片文件]
    C --> D{格式/大小校验}
    D -->|不通过| E[返回错误]
    D -->|通过| F[UUID重命名保存到uploads/]
    F --> G[OCR识别]
    G --> H[OpenCV预处理: 灰度→去噪→二值化]
    H --> I[正则匹配15种体检指标]
    I --> J[规则引擎生成通俗解读]
    J --> K[写入tb_physical_report]
    K --> L[返回报告详情]
```

| 低密度脂蛋白 | <3.4 mmol/L | 坏胆固醇 |
| 尿酸 | 男<420 / 女<360 μmol/L | 痛风风险 |

| 谷丙转氨酶 | 0-40 U/L | 肝功能 |
| 谷草转氨酶 | 0-40 U/L | 肝功能 |
| 白细胞 | 4-10 ×10⁹/L | 感染/免疫 |

## 四、数据模型总览

### 4.1 核心数据表

| 表名 | 说明 | 核心字段 |
|------|------|----------|
| tb_user | 用户表 | username, password, user_type, real_name, id_card |
| tb_elder_bind | 长辈绑定 | child_uid, elder_name, elder_id_card, medical_card |

| tb_doctor | 医生 | doctor_name, dept_id(FK), specialty, register_fee |
| tb_schedule | 排班 | doctor_id(FK), work_date, time_period, normal_num, elder_priority_num |
| tb_reserve | 预约订单 | user_id(FK), schedule_id(FK), queue_code, pay_status, order_status |
| tb_pay_record | 支付记录 | reserve_id(FK), out_trade_no, trade_no, pay_channel, pay_status |
| tb_volunteer | 志愿者 | vol_name, service_dept, service_score, service_count |

| tb_health_reminder | 健康提醒 | user_id(FK), remind_type, remind_time, repeat_days |
| tb_message | 消息 | user_id(FK), msg_type, msg_content, read_status |
| tb_physical_report | 体检报告 | elder_bind_id(FK), report_url, ocr_result, interpretation |

### 4.2 状态枚举汇总

**订单状态 (order_status)**: 1=待支付 → 2=已预约 → 3=已就诊 → 4=已取消

**支付状态 (pay_status)**: 1=待支付 → 2=已支付 / 3=超时取消

**候诊状态 (queue_status)**: 1=等待中 → 2=就诊中 → 3=已完成

**陪诊订单状态**: 1=待审核 → 2=待服务 → 3=服务中 → 4=已完成 / 5=已取消

**用户类型 (user_type)**: 1=老年用户 / 2=子女用户 / 3=管理员
