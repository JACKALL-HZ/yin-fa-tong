## 1. 延时队列：支付超时自动取消

### 1.1 业务场景

用户预约挂号后，需要在 15 分钟内完成支付。超时未支付的订单需要自动取消，并释放被占用的号源。这是一个典型的**延时任务**场景。

### 1.2 技术选型

采用 **RabbitMQ 的延迟消息插件**（`rabbitmq_delayed_message_exchange`），而非定时轮询数据库。优势：

- **精确**：消息到达延迟时间后立即投递，不受轮询间隔影响
- **高效**：无需定时扫描全表，数据库压力小
- **可靠**：消息持久化，RabbitMQ 重启不丢失

### 1.3 交换机与队列设计

**代码位置**：`backend/app/shared/rabbitmq.py`

系统声明了 4 个交换机：

```
ex_reserve   → DIRECT  → q_reserve_notify   (挂号成功通知)
ex_queue     → DIRECT  → q_queue_notify     (候诊顺位通知)
ex_accompany → DIRECT  → q_accompany_notify (陪诊申请通知)
ex_delay     → X_DELAYED_MESSAGE → q_delay_tasks (延时任务)
```

关键代码（`rabbitmq.py:45-50`）：

```python
ex_delay = await _channel.declare_exchange(
    "ex_delay",
    aio_pika.ExchangeType.X_DELAYED_MESSAGE,  # 延迟消息交换机
    durable=True,
    arguments={"x-delayed-type": "direct"},    # 延迟结束后用 direct 路由
)
```

`X_DELAYED_MESSAGE` 不是 RabbitMQ 原生类型，需要安装 `rabbitmq_delayed_message_exchange` 社区插件。消息发布到该交换机后，Broker 会持有消息直到延迟时间到达，再按 `x-delayed-type` 配置的路由方式投递到绑定队列。

### 1.4 生产者：发送延时消息

### 1.5 消费者：处理超时

**代码位置**：`backend/app/reserve/mq/consumer.py`

```python
async def _handle_message(message: aio_pika.IncomingMessage):
    async with message.process():  # 自动 ACK/NACK
        data = json.loads(message.body)
        reserve_id = data["reserve_id"]

        async with AsyncSessionLocal() as session:
            # WHERE pay_status = 1 幂等守卫
            result = await session.execute(
                sa_update(ReserveModel)
                .where(ReserveModel.id == reserve_id, ReserveModel.pay_status == 1)
                .values(pay_status=3, order_status=4)  # 标记超时取消
            )
            if result.rowcount == 1:
                await session.commit()
                await rollback_source_redis(schedule_id, source_type)  # 释放号源
```

**幂等设计**：SQL 的 `WHERE pay_status = 1` 保证已支付或已取消的订单不会被重复处理。`message.process()` 上下文管理器确保消息在异常时 NACK 重入队。

### 1.7 流程图

```

```

| 层级 | 机制 |
|------|------|
| 订单创建 | 复用 `reserve_id` 下未超时的支付记录 |

## 3. 预约陪诊服务

### 3.1 业务模型

陪诊服务包含两个核心实体：

- **志愿者**（`tb_volunteer`）：可预约的陪诊人员
- **陪诊订单**（`tb_accompany_order`）：用户提交的陪诊申请

### 3.2 状态机设计

**代码位置**：`backend/app/accompany/order/service.py`

订单采用五状态流转：

```
1 待审核 → 2 待服务 → 3 服务中 → 4 已完成
    ↓         ↓         ↓
    5 已取消  5 已取消   (过期自动→4)
```

| 操作 | 状态变更 | 角色 | 接口 |
|------|----------|------|------|
| 提交申请 | → 1 | 用户 | `POST /api/accompany-orders` |
| 审核通过 | 1→2 | 管理员 | `POST /{id}/approve` |
| 审核拒绝 | 1→5 | 管理员 | `POST /{id}/reject` |
| 开始服务 | 2→3 | 管理员 | `POST /{id}/start` |
| 完成服务 | 3→4 | 管理员 | `POST /{id}/complete` |

每次状态变更都校验当前状态，防止非法跳转：

```python
if order.order_status != 1:
    raise BadRequestException("当前状态不允许此操作")
```

### 3.3 时间驱动的自动过期

**代码位置**：`accompany/order/service.py:21-26`

订单序列化时（`_to_response`），根据 `accompany_date` 与当前日期比较，懒更新状态：

```python
if order.accompany_date < date.today():
    if order.order_status in (1, 2):
        order.order_status = 5  # 自动取消
    elif order.order_status == 3:
        order.order_status = 4  # 自动完成
```

这是**读时更新**策略，优点是无需定时任务，缺点是未被查询的订单状态会滞后。

### 5.4 本地规则引擎

```python
def _rule_engine_diagnose(symptom_text: str):
    # 1. 滑动窗口分词（2-5 字）
    tokens = set()
    for size in range(2, 6):
        for i in range(len(symptom_text) - size + 1):
            tokens.add(symptom_text[i:i+size])

    # 2. 匹配症状词库，累加科室权重
    scores = {}
    for token in tokens:
        if token in SYMPTOM_MAP:
            dept, weight = SYMPTOM_MAP[token]
            scores[dept] = scores.get(dept, 0) + weight

    # 3. 取 Top3 科室
    top3 = sorted(scores.items(), key=lambda x: -x[1])[:3]
    if not top3:
        return [("内科", 0.5), ("老年病科", 0.3)]  # 兜底
```

**症状词库**（`guide/symptom_dict/mapping.py`）是一个 Python 字典，映射症状关键词到科室和权重：

```python
}
```

## 6. 注册登录与 JWT 认证

### 6.1 密码安全

**代码位置**：`backend/app/auth/utils.py`

使用 **bcrypt** 算法，每次生成随机盐：

```python
import bcrypt

def hash_password(password: str) -> str:
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt()).decode()

def verify_password(plain: str, hashed: str) -> bool:
    return bcrypt.checkpw(plain.encode(), hashed.encode())
```

- bcrypt 自带盐值，相同密码每次哈希结果不同
- 计算故意慢（~100ms），防暴力破解

### 6.2 JWT Token 设计

**代码位置**：`backend/app/auth/utils.py`

```python
from jose import jwt

def create_access_token(user_id: int, user_type: int) -> str:
    payload = {
        "sub": str(user_id),   # 用户 ID
        "type": user_type,     # 1=老人 2=子女 3=管理员
        "exp": datetime.utcnow() + timedelta(minutes=settings.JWT_ACCESS_TOKEN_EXPIRE_MINUTES),
    }
    return jwt.encode(payload, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM)
```

Token 有效期 24 小时（`JWT_ACCESS_TOKEN_EXPIRE_MINUTES=1440`）。

### 6.3 认证中间件

**代码位置**：`backend/app/auth/service.py`

```python
async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(HTTPBearer()),
    session: AsyncSession = Depends(get_db),
) -> UserModel:
    payload = decode_access_token(credentials.credentials)
    user = await repo.get_user_by_id(session, int(payload["sub"]))
    if not user:
        raise UnauthorizedException("用户不存在")
    return user
```

使用 FastAPI 的 `Depends` 依赖注入，任何需要登录的接口只需声明 `user: UserModel = Depends(get_current_user)`。

### 6.4 管理员权限守卫

```python
async def require_admin(user: UserModel = Depends(get_current_user)):
    if user.user_type != 3:
        raise ForbiddenException("仅管理员可操作")
    return user
```

### 6.5 多端登录支持

**代码位置**：`backend/app/auth/service.py`

| 登录方式 | 实现 |
|----------|------|
| 账号密码 | `login()` — bcrypt 验证 → 签发 JWT |
| 微信登录 | `wx_login()` — 模拟 OAuth，首次自动注册 |
| 支付宝登录 | `alipay_login()` — 真实 OAuth，auth_code 换 token → 获取用户信息 |

支付宝登录流程：

```
前端扫码 → 获取 auth_code → 后端 /alipay-login
    → AlipaySystemOauthTokenRequest 换 access_token + alipay_user_id
    → AlipayUserInfoShareRequest 获取昵称
    → 数据库查找/自动注册 → 签发 JWT
```
